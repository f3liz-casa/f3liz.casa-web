WebTransport over HTTP/3 for Elixir. On real QUIC, talking to real browsers.

experimental · works end to end with Chrome · 58 tests on real QUIC · the API may still move

why it exists

Elixir had no WebTransport server on the BEAM's own QUIC stack. Plug servers stop at TCP. The existing options wrap a whole Rust QUIC stack and live beside Plug rather than with it.

karutte takes the other road: quicer for QUIC, cowlib for HTTP/3 framing, and only the WebTransport-specific parts written here. The runner is plain OTP, so crash isolation and backpressure fall out of the process model instead of being bolted on.

three things a browser could not get from the BEAM before

Datagrams, many independent streams on one connection, and streams the server opens itself. One slip for each, below.

datagrams

Unreliable, unordered, no head-of-line blocking, about 20 ms end to end. WebSocket cannot; WebRTC can, with a whole media stack attached.

many independent streams on one connection

Each with its own flow control, each its own process. A slow consumer of one stream stalls nothing else. A crash in one stream handler is contained to that stream.

server-initiated streams, and routing by path

, so one port can host several unrelated protocols and push without being asked.

the shape

A session is control plane only and never touches stream bytes. A stream is one process. Backpressure has three axes that never overlap: stream creation, bytes per stream, and datagrams, which are dropped rather than queued.

defmodule MyApp.Echo do
  @behaviour Karutte.WebTransport

  def init(_arg, ci),
    do: {:ok, %{t: ci.transport, conn: ci.conn}}

  def handle_stream(_stream, _dir, s),
    do: {{:handler, MyApp.Echo.Stream, nil}, s}

  def handle_datagram(bin, s) do
    s.t.send_datagram(s.conn, bin)
    {:ok, s}
  end

  defmodule Stream do
    @behaviour Karutte.WebTransport.Stream
    def init(_stream, _arg), do: {:ok, %{}, active: true}
    def handle_in(bin, s), do: {:push, bin, s, active: true}
    def handle_fin(s), do: {:close_write, s}
  end
end

{Karutte.Http3.Server,
 port: 4433, certfile: "cert.pem", keyfile: "key.pem",
 handler: MyApp.Echo}

That is a complete echo server. active: is the flow-control window, handed to you. Leave it out to push back on the peer.

built on it so far

  • sukhi bridgea fediverse server's live timeline, one stream per feed, so a busy feed never delays a quiet one
  • heya (部屋)an audio-only room opened from a Zulip call link. Opus over datagrams, one process per voice, a room that never looks at the bytes

what it is not, yet

  • not for Safari, whose WebTransport support is new and untested here
  • not behind Cloudflare, which does not proxy WebTransport; UDP has to reach the box
  • not a web server: anything but CONNECT is a 404. Serve pages from Bandit next to it
  • not inside Plug or Phoenix. The seam is sketched; the Bandit side is the next real project
  • not load-tested at scale. Hundreds of connections are tested, thousands are not
