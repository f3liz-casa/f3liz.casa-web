sukhi-fedi

すき。ちいさな fediverse のサーバ。

An ActivityPub server for a handful of people, written in Elixir. Mastodon and Misskey clients work with it. The timeline does not scroll forever.

running · since spring 2026, on one small box · v0.4 · Elixir + PostgreSQL + NATS · AGPL-3.0

why it exists

We wanted a fediverse server that could be understood by one person, end to end, and that would not ask for a bigger machine every year. Mastodon is a good neighbour but a large one. So we wrote a small one.

It also became the place to try things: how quiet a timeline can be and still be a timeline, how a follow and a "keep an eye on" should differ, and what it takes to speak both the old and the new HTTP signature dialects to every server out there. natadeco runs on it too, as a different front on the same house.

the name

Three things folded together. Suki, "like", is the sound of Misskey, and of the little Misskey servers people named after it, Sushiskey and the others. And sukhi is Pali, from the Karaṇīya Mettā Sutta: sabbe sattā bhavantu sukhitattā, may all beings be happy. A server you like, that wishes everyone well.

what it is made of

One BEAM, two roles inside it, and two things it leans on:

people ──HTTPS──▶ ┌ gateway ───────────────┐      ┌ delivery ──────────────┐ ──HTTPS──▶ other servers
                  │ Mastodon / Misskey API │      │ outbox relay           │
                  │ inbox, WebFinger, auth │      │ retries, signing       │
                  │ the SvelteKit web UI   │      │ collection sync        │
                  └──────────┬─────────────┘      └───────────┬────────────┘
                             │                                │
                    PostgreSQL (what is true)          NATS (what just happened)

ActivityPub itself, the JSON-LD, the HTTP signatures and the integrity proofs, lives in a folder of plain Elixir with no database in it. Its test fixtures were generated by Fedify, byte for byte, so the two agree on what a signed activity looks like. The web UI is a SvelteKit app built to static files and served from the same process, so there is one thing to run.

three small things it does

  • Stops at the bottom of the page. There is no infinite scroll in any mode, and no timeline refreshes itself. You read what is there and press "more" if you want more. Notifications come in two kinds: someone speaking to you is a plain number, and everything else is a small shape that grows while you are away and resets when you look.
  • Knocks twice. The fediverse is halfway through moving from the old draft-cavage signatures to RFC 9421. sukhi-fedi signs with RFC 9421 first, falls back to the old form once if a server refuses, and remembers the answer per host for a week, so a neighbour that upgrades is noticed on its own. Every actor also carries an Ed25519 key and posts go out with an integrity proof, the way Fedify does it.
  • Has circles that are honest. A circle is a list of people you want to see on their own page. Putting someone in one does not follow them, and taking them out does not unfollow. A circle can also be a gate on your home: hide these people from home entirely, or only their boosts, or only their replies that are not to you.

what it is not

  • not big. One box, a few people, a few hundred posts a month. It has never been run with a thousand users, and nothing here says it would go well
  • not a drop-in Mastodon. The client API is compatible enough for the apps we use; the admin side, filters and a long tail of endpoints are still partial, and Misskey compatibility is thinner than Mastodon's
  • not finished with itself. There is a punch list in the repo and it is honest about what is on it
  • not open for signup. The instance at sukhi.f3liz.casa is invitation only. The code is yours to run
